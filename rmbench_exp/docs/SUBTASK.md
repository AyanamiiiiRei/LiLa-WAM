# 子任务方案（2026-11-05）

问题：把每个任务拆成子任务，LiLa-WAM 只作为"按子任务 VTT 执行"的执行器，由 Sub Task Chooser 决定当前子任务何时结束、
下一个做什么；这样的分工在 RMBench 全部 10 个任务上能否超过同样微调的原模型？

- 子任务：语言标注中连续相同的描述合并为一个子任务（swap_blocks 用事件边界）；子任务类型 = (任务, 描述)，
  子任务 VTT = 该类型所有片段 CLS(末) − CLS(首) 的平均（`scripts/step36_subtask_library.py`，`artifacts/subtasks/`）。
- 执行器输入（接在 64 个视觉 token 之后）：子任务 token = Linear(LN(子任务 VTT)) + 类型嵌入；选中的记忆 token =
  子任务 token 对记忆条目的注意力（条目 0 = 第 0 帧，之后每个完成的子任务一条：首帧 CLS + 末帧 CLS，最多 12 条）。
  类型嵌入是对用户设计的补充：swap_blocks 中三次移动的子任务 VTT 范数只有 0.6–1.5、一致性 0.15，单靠 VTT 难以区分。
- Chooser：2 层 transformer，输入 DiT 最后一层的整条输出序列 + 当前帧 CLS + 当前子任务类型 + 查询 token；
  输出"当前子任务是否结束"和"下一个子任务类型"（只在本任务的类型中选）。不输入已进行的块数（避免学成计时器）。
- 时序约定：每个动作块先用"决定前"的状态在流时间 0 前向一次，Chooser 决定；若结束，用当前帧 CLS 写入记忆条目、
  换子任务类型，再用"决定后"的状态预测本块动作。训练与推理一致，无标签泄漏。
- 方案一（P1，联合）：执行器与 Chooser 一起训练，总损失 = L_fm + 0.5·L_ff + 0.1·L_chooser，Chooser 损失也训练 DiT。
- 方案二（P2，分开）：先只训练执行器（L_fm + 0.5·L_ff），冻结后单独训练 Chooser（`scripts/step38_train_chooser.py`）。
- 从头训练（用户决定）：DINOv3 冻结，训练设置与第一轮基线 baseline-seed0 完全相同（85,928 步、batch 64、学习率 2e-4 → 5e-5，约 17.4 个 epoch，不热启动），基线即为匹配的对照。
- 本轮不含失败标签（演示中没有失败；见讨论记录），失败记忆与重做留到之后。
- 评测：每组 10 个任务 × 50 次，种子与第一轮相同，配对比较（`analysis/subtask_summary.py`）。
- 局限：子任务库用了全部 50 条演示（含每任务 2 条留出演示，只影响类型均值）；每组一个训练种子。

运行：`bash scripts/step39_subtask_smoke.sh`（先检查）→ `bash scripts/step40_subtask_all.sh`（全部，后台，约 3 天）。

## 结果（2026-11-08，每组 10 任务 × 50 次，种子与第一轮相同；P1、P2 与基线训练设置相同、均从头训练）

| 任务 | 基线 | P1 联合 | P2 分开 | P2 vs 基线（仅 P2 / 仅基线，p） |
|---|---|---|---|---|
| cover_blocks | 0 | 1 | **9** | 9 / 0, p = 0.0039 |
| swap_blocks | 7 | 6 | **17** | 16 / 6, p = 0.052 |
| swap_T | 3 | 4 | 6 | 5 / 2, p = 0.45 |
| observe_and_pickup / put_back_block / place_block_mat | 2 / 0 / 0 | 2 / 1 / 0 | 3 / 1 / 1 | 均 p = 1 |
| press_button | 0 | 0 | 0 | – |
| battery_try | 20 | **3** | 18 | 12 / 14, p = 0.85 |
| rearrange_blocks | 8 | 2 | 4 | 3 / 7, p = 0.34 |
| blocks_ranking_try | 11 | 6 | 4 | 3 / 10, p = 0.092 |
| 合计 | 51/500 | 25/500（vs 基线 p = 0.0026） | 63/500（p = 0.25） | |

- Chooser 离线（20 条留出演示、64 个子任务结束点）：P1 F1 0.95、P2 F1 0.95，下一子任务准确率均 0.95。
- 训练末 200 步 L_fm：基线 0.0024、P1 0.0037、P2 0.0019。联合训练中 Chooser 损失（λ = 0.1）拖累了执行器的拟合。
- 闭环中 Chooser 的切换序列：swap_blocks 中 P1 44/50、P2 49/50 回合按 移动 1 → 2 → 3 → 按按钮 切换；
  P1 与 P2 序列相近而成功率 6 vs 17，差别在执行。blocks_ranking_try 中 P2 有 33/50 回合从未切换
  （离线 F1 高，闭环中卡在第一个子任务）。
- 解读：P2 在需要"按进度/按记忆选下一步"的 cover_blocks 上显著提高（经 10 个任务的 Bonferroni 校正后仍显著），
  swap_blocks 接近显著；合计提高不显著。P1 显著变差，主要来自 battery_try（20 → 3）。
- 局限：每方案一个训练种子；闭环未运行 oracle，切换时刻是否正确无法核对；留出演示只有 20 条。

### blocks_ranking_try 中 P2 不切换的原因（2026-11-09，基于闭环记录，未重跑模型）

- 33/50 回合整局（219 个动作块，超时）停在第一个子任务"按按钮"，全部失败；切换过的 17 回合，第一次切换都发生在
  第 3–9 块（演示中第一次按按钮在第 5 块结束），之后没有任何回合在更晚的时刻补上切换。
- 机器人状态（policy_view/*.npz）：所有回合左臂在第 48 步左右到达按钮上方、夹爪闭合。更正：起初只看了到起点的距离
  （约 0.236 m 不变），误判为"停在按下的姿态"；看高度 z 才发现，切换过的回合按下约 3.4 cm 后抬起一次（演示为 4 cm），
  未切换的回合则反复按下、抬起（z 在 0.93–0.96 m 间往复），即执行器在"按按钮"条件下重复按按钮。按钮是否被仿真器
  记为按下（press_cnt）从现有记录中无法得知。
- 原因（训练设计的缺口）：Chooser 的训练样本只有"决定前"的正确状态——在子任务真正结束的那一块标为"结束"，
  之前标为"继续"；从未见过"该结束的时刻已经过去、类型却还停在旧子任务"的状态。所以错过结束时刻后，它没有学过补切换，
  而执行器只会重复按按钮，形成循环。（第 2 期切换判断头的训练中加入了"落后一步"的样本，这里没有。）
- 另一现象：之后的"按按钮"子任务在闭环中都只持续 1 个动作块就被切走（演示中约 3 块），按钮可能根本没被按下。
  推测原因：Chooser 只看当前帧和已完成子任务的记忆，"刚进入按按钮、还没按"与"已经按完"两种画面相近，它没有当前子任务内的历史。未验证。

更正：`p2_failures.py` 把 swap_blocks 的 33 个失败标为"执行"，按时间对齐后应为子任务判断（Chooser 过早切到"按按钮"，执行器照做）。

结论：
- 与第一轮（记忆 73%、操作 21%）相比，决策层失败（记忆 + 子任务判断）仍占 74%，精度类 24%，比例基本没变；P2 的提升没有改变瓶颈。
- 子任务判断：两种方向都有——结束过早（swap_blocks、press_button）和从不结束（blocks_ranking_try、put_back_block）。
  结束判断与子任务是否在物理上完成没有对上。Chooser 只看当前帧和已完成子任务的记忆，看不到当前子任务开始时的画面。
  press_button 的标注把同一按钮的多次按压合成一个子任务，按了几次没有进入记忆。
- 记忆：cover_blocks 的打开顺序接近随机（P2 的 9 次成功约等于随机选对顺序的期望 8.3 次），所以 P2 在该任务上的提升来自
  完整执行了 6 个子任务，而非记住颜色。设计上的缺口：下一子任务由 Chooser 选，而 Chooser 只能通过 DiT 输出间接看到记忆，
  且被选中的记忆 token 是按"当前"子任务选的，不是按"下一个"。observe_and_pickup 与 place_block_mat 的目标由执行器的记忆 token 决定。
- 局限：battery_try、observe_and_pickup、blocks_ranking_try 的部分标签来自少量抽查；place_block_mat 为 20 回合外推；一个训练种子。
